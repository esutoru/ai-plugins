# Wordmine settings

Shared definition of the user's Wordmine settings: where they are stored, what they contain, and how skills read and write them. The setup skill collects the values once (the deck through `deck.md`, the note type name through `note-type.md`, the languages with its own question) and saves them here; every other skill loads them before touching Anki.

Skills import this file and call its workflows. Follow them inline, in the current conversation. The rules for talking to Anki from `anki-connect.md` apply: warn before running a command, and never write anything without saying so first.

## File

| Setting | Value |
|---|---|
| Path | `~/.config/esutoru-wordmine/config.json` on every platform (`$HOME/.config/...`; in Git Bash and PowerShell on Windows `$HOME` resolves to the user profile) |
| Format | JSON object, UTF-8, two spaces indentation |

```json
{
  "deck": "Wordmine",
  "noteType": "Esutoru Wordmine (k3x9m2qa)",
  "targetLanguage": "English",
  "sourceLanguage": "Russian"
}
```

| Key | Meaning | Default |
|---|---|---|
| `deck` | Anki deck that receives new Wordmine cards unless the user names another deck when calling a card-making skill. | none; chosen in setup through `deck.md` (`Wordmine` is the suggested name for a new deck) |
| `noteType` | Name of the Wordmine note type in the collection. | `Esutoru Wordmine (<8 random characters>)`, generated by `note-type.md` |
| `targetLanguage` | The language the user is learning. The word, the phrase and the example on a card are in this language; it is the question side. | `English` |
| `sourceLanguage` | The user's own language. The translation, the translated example and the notes are in this language; it is the answer side. | `Russian` |

Language values are language names in English, capitalised (`English`, `Russian`, `German`, `Japanese`). Accept whatever the user types and store the English name.

Unknown keys are kept as they are. A missing or empty key is treated as not yet chosen: the setup skill asks for that value only, keeps everything else untouched, and rewrites the file. Values that are present are never re-asked or overwritten; the user changes them by editing the file.

Card-making skills do not ask for missing values. When any of the four keys is missing or the file cannot be read, they stop and tell the user to run the setup (see `preflight.md`).

## Reaching the file from a sandbox

The agent sandbox may block shell access to the home directory. Try the options in this order and stop at the first one that works. Explain the reason once: "Your settings live at `~/.config/esutoru-wordmine/config.json`, which the sandbox does not cover."

1. **File tools.** In Claude Code use the `Read` and `Write` tools; they run outside the Bash sandbox and a write outside the project only triggers the usual permission prompt. Prefer them over `cat` and heredocs for this file.
2. **One shell command outside the sandbox.** If there are no file tools or they were denied, run the single `cat` (read) or `mkdir -p` + `cat >` (write) command outside the sandbox right away; the user's tool shows its own approval prompt if needed. Do not ask your own question first, and never ask to disable the sandbox for the whole session.
3. **Manual fallback.** If that is denied or fails, show the exact JSON and path under the bold heading **Your steps** (**Save this file** at the path, with the JSON in a code block) and ask them to save it themselves, or, for reading, collect the values again (deck through `deck.md`, note type through `note-type.md`, languages with the setup question) and use them for this conversation only. Report the settings as `to do` with the instruction "Save the settings file manually".

## Workflows

```flowmd
let config_path = "~/.config/esutoru-wordmine/config.json"
let defaults = record { deck: "", noteType: "", targetLanguage: "", sourceLanguage: "" }
let default_languages = record { targetLanguage: "English", sourceLanguage: "Russian" }

workflow "load" () {
  step "Warn" {
    summarize "I will read your Wordmine settings from $config_path."
  }

  step "Read" {
    read $config_path following the sandbox order above
    if the file does not exist {
      return record { status: "missing", config: $defaults }
    }
    if the file could not be read {
      return record { status: "unreadable", config: $defaults }
    }
    if the file is not valid JSON {
      summarize "The settings file is not valid JSON. I will treat it as missing and offer to rewrite it."
      return record { status: "missing", config: $defaults }
    }
    let config = $defaults merged with the file's values, empty strings for missing keys
    return record { status: "ok", config: $config }
  }
}

workflow "save" (config) {
  step "Warn" {
    summarize "I will write these settings to $config_path, creating the folder if needed:"
    show $config as JSON
  }

  step "Write" {
    write $config_path following the sandbox order above
    if written {
      return "saved"
    }
    show the JSON and the path and ask the user to save it themselves
    let answer = ask "Did you save the file?" {
      "Yes, saved": "I will read it back",
      "Skip for now": "I will use these values for this conversation only"
    }
    if $answer is "Yes, saved" {
      return "saved"
    }
    return "not-saved"
  }
}
```
